# Правила работы ассистента

- Перед изменением файлов — сначала показать план и дождаться подтверждения.
- По умолчанию давать готовый код в чат для ручной вставки; самому редактировать
  файлы — только когда явно попросят.
- При каждой правке показывать в чате пару «Было → Стало» для сравнения.
- В чате не выводить целые файлы — только изменяемые куски.

## Макет-источник: cpahunter_170.html

- В корне проекта лежит файл `cpahunter_170.html` — это макет, свёрстанный
  другой ИИ. Используем его ТОЛЬКО как референс (источник кусков вёрстки).
- При переносе кусков из макета в blade-файлы проекта:
  - классы макета не копировать как есть;
  - переводить вёрстку на понятные классы проекта — по образцу уже существующих
    (`.container`, `.section`, `.section-title`, `.btn`, БЭМ-подобные имена
    вроде `.calc-btn__label`, `.brand-shop__pros` и т.п.).
- Уже перенесённые блоки/классы: `author-case__*`, `author-cta__*`
  (история автора + CTA), `journey__*`, `tactics-*`, `platform-link-grid`,
  `pl-link-card*` (страницы программ).
- Сейчас работаем ТОЛЬКО на странице `views/pages/program-page.blade.php`
  (роут `/program-page`). Все блоки для неё берём из макета
  `cpahunter_170.html`. Структурный референс в макете — `.page-niche-beauty`.
- Правило: если что-то непонятно по задаче — СНАЧАЛА задать короткий вопрос,
  а не гадать и не писать длинные тексты. Не делать лишних шагов без явного
  запроса (например, не выносить блоки в компоненты/данные, если не просили).
- Меньше воды: отвечать кратко, без разжёвывания и лишних пояснений.
  Показывать только код/правку и результат, не описывать процесс словами.
- Не показывать в чате сервисные шаги: поиски по макету, grep, какие строки
  читал, промежуточные выводы «нашёл блок». Всё это выполнять тихо, в чат
  выводить только итог (что сделал / готовый код / вопрос по задаче).
- Сам файл макета не редактировать.

## Передача проекта

- Это прототип (вёрстка/фронт): в итоге проект будет передан
  бэкенд-специалисту, который «натянет» страницы на реальные данные.
- Отсюда правила: данные — через `views/data/*.php`, AJAX-фрагменты — через
  заголовок X-Fragment, логику в шаблонах не хардкодить, классы держать
  человекочитаемыми и переиспользуемыми.

## Контекст проекта (из референса другой ИИ, перевод)

CPA Hunter — CPA-платформа для блогеров и креаторов. Идёт миграция
монолитного HTML-макета в компонентную архитектуру (BladeOne/PHP,
ванильный JS/CSS). В работе: публичные страницы, кабинет, юр. страницы.

- Стек: BladeOne/PHP, ванильный JS/CSS, FontAwesome (иконки только через
  `<i>`, никогда SVG), шрифт Inter, flag-icons, кастомный `.po`-парсер для
  i18n (русский URL без префикса, остальные языки — `/en`, `/es`, ...).
- Инфраструктура: GitHub `github.com/univerblog/New-spa-hunter`, деплой
  через VS Code SFTP на Beget (`test.gelay.ru`). Разработка на Windows,
  сервер Linux.
- Источник истины: макет-донор. Все значения стилей (размеры, цвета,
  отступы) брать ТОЛЬКО из макета через поиск, не выдумывать.
  У нас в корне — `cpahunter_170.html` (в референсе фигурирует обрезанная
  копия `cpahunter_maket_lite.html`).

### Состояние по референсу

- Юр. страницы: 6 роутов (`/terms`, `/privacy`, `/compliance`, `/dnss`,
  `/cookie`, `/cookie-settings`) → `views/pages/legal/*.blade.php`; общий
  `legal-nav` (на десктопе pill-меню, на мобиле дропдаун — без нового JS,
  переиспользует `dropdown-block` из `my.js`); двухколоночный лейаут со
  sticky-оглавлением и скроллспаем (`spyLock`, `overscroll-behavior: contain`);
  dnss/cookie-settings — чекбоксы с localStorage + cookie и GPC. Классы —
  человекочитаемые (`legal-layout`, `legal-left-nav`, `optout-*`, `consent-*`).
- `program-page` (`/program-page`): готовы breadcrumb, hero и «Топ детских
  магазинов» (`components.shops-category`). Дальше — калькулятор (секция #4);
  структурный референс в макете — `.page-niche-beauty` (у `#niche-parenting`
  только CSS-правило, разметки нет).
- Кабинет: собран полностью (дашборд, источники трафика, баланс, вывод,
  налоги, уровень, рефералка, уведомления, настройки, статистика,
  онбординг `/cabinet-start`).
- Главная: hero, карточки авторов, сетка ниш, уровни лояльности, earn-cta
  со счётчиком при скролле, `.niches`/`.niches--curated`, `.home-ref-section`,
  live-stats тикер, FAQ (7 табов, 45 вопросов, `data-goto`), `faq-short`,
  `.brand-shop` с раскрытием.

### Ключевые принципы (из референса)

- Работа строго по шагам: сначала согласовать HTML-структуру, потом CSS.
  Каждый шаг — с явным подтверждением.
- Никогда не выдумывать значения CSS — grep по макету.
- AJAX-фрагменты: заголовок X-Fragment перехватывается в роутере до рендера
  страницы; после замены DOM через outerHTML вызывать `window.initSelects()`.
- Данные: `views/data/*.php` — ассоциативные массивы с lookup-картами;
  компоненты используют статический кэш. Иконка/подпись живут в карте,
  строки ссылаются по ключу.
- Самодостаточность компонентов: логика данных, разметка, пагинация и JS —
  в одном blade-файле; JS — в `@push('scripts')` компонента, не в `my.js`
  (если не универсально).
- Кастомные селекты: `data-select` шлёт `select:change` с
  `detail.value/label`; `data-select-ready` защищает от повторной инициализации.
- Модалки: один `modal-window`, несколько `.modal-content`; статичные —
  через `@push('modals')`, динамические — innerHTML в `#modal-dynamic`;
  API `openModal(id)`.
- Аккордеоны: `ACCORDION_TYPES` в `my.js`; `start-open` — стартовое состояние
  (отдельно от runtime `is-open`); `data-open-first` на уровне обёртки.
- Фикс float в `json_encode`: `ini_set('serialize_precision', -1)`.
- iOS: `font-size: 16px` на мобильных инпутах (запрет зума).
- hover-правила — только внутри `@media (min-width: 1200px)`.
- Без `type="button"` вне форм.
- БЭМ для вложенных блоков: короткие читаемые классы; переиспользовать
  существующие паттерны, новые классы — только при необходимости.
- Состояние на сервере (PHP-сессии) вместо localStorage; AJAX возвращает
  готовые HTML-фрагменты.

### Правила доставки кода (из референса)

- Не дублировать уже показанный код — только новый целевой блок.
- CSS: один селектор на строку, все свойства в одну строку.
- JS: полная замена функции, без диффов.
- Общение: по-русски, кратко, без лести, без непрошеных советов.
